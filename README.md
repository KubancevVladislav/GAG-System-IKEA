# RAG-поиск по публикациям о визуальном поиске товаров

Лабораторная работа № 3, вариант 2. Задача - находить научные публикации о поиске товаров по изображению и отвечать по найденным фрагментам со ссылками. Прикладной пример для IKEA - поиск мебели и предметов интерьера по фотографии. Источники - публикации arXiv о визуальном поиске товаров, сопоставлении фотографий и смежных методах компьютерного зрения.

## Запуск

Для запуска нужны Windows, Python 3.12, свободное место под зависимости и примерно 6,3 ГБ видеопамяти под веса.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cu128 "torch==2.8.0+cu128"
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Откройте `solution.ipynb` в PyCharm или Jupyter с рабочей папкой в корне проекта.
Выберите интерпретатор `.venv\Scripts\python.exe` и нажмите `Run All`.

## Методика

1. Собираем метаданные arXiv по запросам о товарах, электронной коммерции и визуальном поиске. Фильтр проверяет тему по заголовку и аннотации. Заголовок и аннотация объединяются в документ. [Ограничения arXiv API](https://info.arxiv.org/help/api/tou.html).
2. Разбиваем документы скользящим окном на Python и `RecursiveCharacterTextSplitter`. Целевой размер - 130 слов, перекрытие - 25 слов. У рекурсивного разбиения фактические границы и перекрытие зависят от разделителей. Для каждой стратегии строим свой FAISS `IndexFlatIP` на нормализованных векторах BGE. `retrieve` возвращает чанки, оценки косинусного сходства и исходные метаданные.
3. Исправляем опечатки через RapidFuzz и частотный словарь корпуса. Слово меняется при единственном допустимом кандидате на расстоянии одной операции Дамерау - Левенштейна. Аббревиатуры, смешанный регистр, числа, дефисы, известные и неоднозначные слова сохраняются. Простое множественное число на `s` сохраняется, когда известна основа.
4. Сравниваем Qwen без контекста и с RAG на пяти сценариях. RAG цитирует источники по идентификаторам из выдачи. При недостатке сведений или при ссылках, которые не прошли проверку формата после повтора, конвейер выдаёт `Информация в найденных статьях отсутствует`.
5. Оцениваем поиск на 100 заголовках. Все чанки статьи считаются релевантными. Считаем Recall, Precision, MRR, Hit Rate и сходство на глубинах 1, 3, 5 и 10. На тех же эталонах проверяем эффект очистки 40 программно искажённых заголовков.
6. Оцениваем генерацию в RAGAS на 16 вопросах с ответом и четырёх без ответа. Генератор выбирает точную цитату из случайно отобранной аннотации и формулирует вопрос. После сверки с аннотациями два вопроса уточнены, эти правки входят в ноутбук и применяются автоматически. Сравниваем `top_k = 1, 3, 5`. Считаем Faithfulness, Answer Relevancy, Context Precision и Context Recall. Для вопросов без ответа отдельно считаем точные отказы и ответы с неподтверждёнными утверждениями. [Метрики RAGAS 0.2.15](https://docs.ragas.io/en/v0.2.15/concepts/metrics/available_metrics/).

### Модели

| Роль                                     | Модель                                                     | Ревизия                                    |
|------------------------------------------|------------------------------------------------------------|--------------------------------------------|
| Эмбеддинги для поиска и Answer Relevancy | BAAI/bge-small-en-v1.5, CPU                                | `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a` |
| Генератор                                | Qwen/Qwen2.5-3B-Instruct, Transformers                     | `aa8e72537993ba99e69dfaafa59ed015b17504d1` |
| Судья                                    | Qwen/Qwen2.5-3B-Instruct, локальный адаптер `BaseRagasLLM` | `aa8e72537993ba99e69dfaafa59ed015b17504d1` |

На CUDA Qwen работает с весами FP16. Генерация и оценка выполняются последовательно с жадным декодированием. При пробе отдельный судья Qwen 1.5B счёл конкретный подтверждённый ответ уклончивым и присвоил ему нулевую Answer Relevancy. Для полного эксперимента выбрана одна модель в обеих ролях. Это ограничивает независимость оценки. В Answer Relevancy используется один обратный вопрос, поскольку повторный вызов с тем же промптом и жадным декодированием выдаёт ту же формулировку. Служебные номера источников убираются перед семантической оценкой, а исходные ответы со ссылками сохраняются.

## Результаты и выводы

Сохранён корпус из 300 уникальных публикаций. Скользящее окно дало 617 чанков, рекурсивное разбиение - 615. Медианная длина составила 130 и 110 слов соответственно.

| Метрика поиска  | Скользящее окно  | Рекурсивный разрез  |
|-----------------|-----------------:|--------------------:|
| Hit Rate@1      |            0,990 |               0,970 |
| Recall@5        |            0,753 |               0,767 |
| Recall@10       |            0,768 |               0,798 |
| MRR@10          |            0,995 |               0,985 |

Обе стратегии находят статью в первых пяти результатах на всех 100 заголовках. Совпадение запроса с заголовком облегчает задачу. При `k=10` найдено 56 из 107 релевантных чанков без заголовка у скользящего окна и 60 из 104 у рекурсивного разреза. На этом корпусе рекурсивный разрез немного повышает полноту на глубинах 5 и 10, а скользящее окно чаще возвращает релевантный чанк первым.

Очистка вернула 29 из 40 заголовков к исходному написанию. Для рекурсивного разреза Recall@5 вырос с 0,758 до 0,796, а MRR@10 - с 0,946 до 0,975. Для скользящего окна Recall@5 остался 0,763, а MRR@10 вырос с 0,975 до 0,988.

В пяти сценариях сравнили ответы одной модели. RAG сослался на PRISM и верно указал SigLIP и 35 кандидатов, а по работе SK Planet нашёл конкретные признаки цвета и внешнего вида. На вопрос о вымышленном испытании IKEA модель без контекста описала его якобы реальные цели. RAG вернул точный отказ. Все ответы и источники приведены в разделе 5 ноутбука.

### Абляция RAGAS

| `top_k`  | Faithfulness  | Answer Relevancy  | Context Precision   | Context Recall  |
|---------:|--------------:|------------------:|--------------------:|----------------:|
|        1 |         0,526 |             0,858 |               0,875 |           0,927 |
|        3 |         0,508 |             0,871 |               0,865 |           0,969 |
|        5 |         0,582 |             0,840 |               0,801 |           0,948 |

При `top_k=3` ответы наиболее релевантны по оценке судьи. При `top_k=5` выше Faithfulness, но ниже Answer Relevancy и Context Precision. Для Faithfulness рассчитаны 15, 15 и 14 оценок соответственно. Ответы с отказом не содержат фактических утверждений, по которым можно посчитать метрику. Для остальных трёх показателей рассчитаны все 16 оценок на каждой глубине.

Для четырёх контрольных вопросов без ответа на каждой глубине получено 4 правильных отказа из 4 и 0 ответов с неподтверждёнными утверждениями. `Abstention accuracy` составила 100%, `hallucination rate` - 0% в этом поднаборе.

Высокая полнота поиска по заголовкам не гарантирует обоснованный ответ на содержательный вопрос. При `top_k=3` нашлись 16 из 16 исходных статей и 14 из 16 полных эталонных цитат. Например, для `qa-01` исходная статья была в выдаче, но необходимое значение 93,51% не попало в три переданных чанка. Конвейер отказался, хотя судья выставил Context Recall 1,000. Поэтому качество контекстов оценивали по метрикам и по конкретным фрагментам.
